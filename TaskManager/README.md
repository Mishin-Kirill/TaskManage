# TaskManager — лабораторная работа №6

Учебный командный проект для демонстрации Feature Branch Workflow.

## Возможности
- добавление задач;
- просмотр списка задач;
- изменение названия и описания;
- удаление задач;
- отметка выполнения;
- поиск по названию и описанию;
- фильтрация по статусу;
- сохранение задач в localStorage браузера.

## Запуск
Откройте `index.html` в браузере. Сборка и установка зависимостей не требуются.

## Командное распределение
1. Участник 1 — `index.html`, `css/style.css`, `js/main.js` (основа интерфейса, хранение и отображение).
2. Участник 2 — `js/add-task.js` (добавление задач).
3. Участник 3 — `js/edit-delete.js` (редактирование, удаление, смена статуса).
4. Участник 4 — `js/search.js` (поиск и фильтрация).

## Общий API
Модули используют объект `window.TaskManager`, который объявлен в `js/main.js`:
- `addTask(title, description)`
- `getTasks()`
- `updateTask(id, changes)`
- `deleteTask(id)`
- `render(optionalTasksArray)`

Скрипты подключены в `index.html` в правильном порядке: сначала `main.js`, затем остальные модули.

## Feature Branch Workflow
Каждый участник работает в отдельной ветке `feature/...`, отправляет её на GitHub и создаёт Pull Request в `main`. Изменения вливаются в `main` после проверки. Не работайте напрямую в `main`.

## Важное правило для параллельной работы
Чтобы избежать конфликтов, каждый участник изменяет только файлы своей зоны ответственности. Если нужно изменить общий API или HTML-контракт, сначала согласуйте это со всей командой и внесите изменение через отдельный Pull Request.
